## 2. 理论框架

### 2.1 核心构念：认知债务（Cognitive Debt）

定义：用户借助 AI 完成结果 R 时，R 所依赖的关键判断、边界条件、验证方法与取舍逻辑
中，用户**尚未证明**自己能复述、验证或迁移的部分。操作性定义（白皮书公式）：

```
认知债务 = AI 代劳成果 − 用户已证明可理解/复述/验证/迁移的部分
```

与相邻构念的区别：
- **知识缺口（knowledge gap）**：课程体系视角的"还没学"；认知债务是工作流视角的
  "刚用掉但没理解"，有明确产生时点、产生场景和证据链。
- **认知外包（cognitive offloading）**[gerlich_2025_cognitive_offloading]：描述行为
  倾向；认知债务是外包行为在该次任务上留下的**可清算存量**。
- **cognitive debt（Kosmyna 2025）**[kosmyna_2025_cognitive_debt]：EEG 实验中的组间
  状态差异；本项目把它工程化为逐条、可累积、可清偿的账目。

### 2.2 机制假设（学习科学依据）

| 产品机制 | 学习科学机制 | 依据 |
|---------|------------|------|
| 费曼卡（复述即检验） | 测试效应/提取练习 | [roediger_2006_testing][karpicke_2008_retrieval] |
| 间隔复训调度 | 间隔效应 | [cepeda_2006_spacing] |
| 微课"不舒服"的追问 | 必要难度 | [bjork_1994_desirable] |
| 低信息密度卡片 + 眼镜单行渲染 | 认知负荷管理 | [sweller_1988_cognitive_load] |
| 欠条优先级排序（练习测试/分布式/解释性提问 高于 重读/划线） | 十种技术效用分级 | [dunlosky_2013_techniques] |
| AI 导师对话式清偿 | 导师系统有效性与粒度 | [vanlehn_2011_tutoring][bloom_1984_two_sigma] |
| 多维画像不贴单一总分 | AI 收益因经验/任务而异 | [brynjolfsson_2023_genai_work][paradis_2024_rct] |

### 2.3 差异声明（与已有工作的关系）

1. 对 **NBER/CHI/METR** 一类"AI 对生产力/批判性思维的影响"研究：它们测**人群平均效应**，
   本项目测**个体账目与清偿路径**，单位是"一条欠条的生命周期"。
2. 对 **Duolingo/Anki** 一类间隔重复系统：它们的卡片来自课程或用户自建；本项目卡片
   从**真实 AI 工作痕迹**自动生成（MCP 捕获 / 视频消化），学习对象是"你刚做过的东西"。
3. 对 **NotebookLM/BibiGPT** 一类内容消化产品：它们止步于摘要；本项目把消化产物
   转成带证据等级的债务对象并进入清偿闭环。

## 3. 测量框架

### 3.1 证据等级 E0-E5（构念的操作化刻度）

| 等级 | 定义 | 系统内对应 |
|-----|------|----------|
| E0 | 无任何理解证据（仅发生过使用） | 新建欠条默认态 |
| E1 | 初次补偿：读过卡片/答案 | 首次复习完成 |
| E2 | 延迟回忆：隔一段时间独立复述 | delayed_recall 通过 |
| E3 | 误概念检查：能识别错误解释 | misconception_check 通过 |
| E4 | 情境迁移：在新任务中正确调用 | scenario_transfer 通过 |
| E5 | 真实工作验证：在实际项目里解决过 | real_work_validation 证据 |

E0-E5 的阶梯映射到 VanLehn 的交互粒度思想与 Bloom 掌握学习：清偿不是布尔量，
是**证据强度的单调爬升**。每次等级跃升必须留下行为证据（不是自评）。

### 3.2 已在系统内落地的测量点

- `training_store`：cognitiveDebts（N=208 历史样本）、masteryProfiles 六维
  （概念理解/独立回忆/提示独立性/误概念抵抗/迁移/保持）。
- `pm_agent_sessions.analysis.cognitiveDebtCandidates`：候选生成与人工 accept 率
  （= RQ2 准确率的原始数据，已在 SQLite 累积）。
- 眼镜 quiz 事件（g2_gesture/answer 提交）与 `evidence` 路由：RQ3 的行为流水。
- B 站消化产物（insights/cards/debtCandidates 三元组 + 导入/accept 漏斗）：RQ4 数据。

### 3.3 关键效度威胁（预先声明）

1. **自证循环**：系统自己出题、自己判分。缓解：E3 以上等级引入外部锚点
   （真实 commit、可运行验证、他人追问）。
2. **候选假阳性**：AI 生成的欠条可能不是用户真欠的。缓解：accept 是人工动作，
   拒绝率本身是测量对象。
3. **单被试外推**：主要数据来自 1-3 名开发者。定位为**单被试纵向设计 + 基线对照**，
   不做人群宣称。

## 4. 实验设计

### EXP-1（RQ2，可立即做）：候选识别准确率审计
- 设计：回放 208 条历史欠条 + 三个 MCP 源的 agent-session 候选，人工标注
  "该候选是否对应一次真实的未理解事件"。
- 指标：precision / recall / accept 延迟。已有数据，无需新采集。

### EXP-2（RQ3，1-2 月）：眼镜清偿 A/B
- 设计：同一欠条池，A 组走眼镜碎片清偿（语音 quiz + 时间轴卡片），B 组只看
  web 列表（无主动提取）。两周后 E2 盲测（web 端统一出题，不告知来源组）。
- 指标：E2 通过率、遗忘曲线形态、清偿动作完成率。
- 预注册：指标、时长、剔除规则在实验开始前写入 docs/research/EXP-2-PREREG.md。

### EXP-3（RQ4，随 SESSDATA 解锁）：视频消化质量评审
- 设计：同一视频的 subtitle 模式 vs metadata_fallback 模式产物，盲评
  "知识点是否值得学/时间轴是否对准/欠条是否成立"（5 点量表，n≥10 视频）。
- 指标：评分分布、卡片导入率、欠条 accept 率。
